Every way of installing is now the same product, and nothing is left out: the app, the **full icon library**, the **ArcGIS map viewer** and the **Python notebooks**.

## Download

| You want | Get |
| --- | --- |
| **An app, no setup** | the installer or portable file for **Windows**, **Linux** (AppImage, deb, rpm, tar.gz) or **macOS** below. Open it: the notebooks and the maps are inside |
| **Docker** | `docker-compose.yml` below, then `docker compose up -d` in the folder where you saved it. Or one command: `docker run -d --name trazo --restart unless-stopped -p 127.0.0.1:3000:3000 -p 127.0.0.1:3001:3001 -p 127.0.0.1:3002:3002 ghcr.io/balalex12/trazo:__VERSION__` |
| **Serve it yourself** | `Trazo-Web-__VERSION__.zip`: unzip it and double click `start-trazo.bat` (Windows) or run `./start-trazo.sh` (Node.js 18+) |
| **Check what you downloaded** | `SHA256SUMS` |

The installers are **not signed**: Windows and macOS will warn the first time (docs/DESKTOP.md says what to click). They are large, a few hundred MB, because the notebooks (Python in your computer, with pandas, scikit-learn and GeoPandas) are inside.

## What is new since v0.2.0

**The same product everywhere.** The desktop app, the web zip and the Docker image used to differ: the installers had no map viewer and needed a separate download for the notebooks, and the published builds left out the Esri Calcite icons and the libraries with third-party brand logos. Now they all carry the full library, the viewer (port 3001) and the notebooks (port 3002), and start them together. The Docker image is one image with all three.

**Clone and one command.** `docker compose up -d --build` builds everything inside Docker into that one image: the icon libraries, the app, the map viewer and the notebooks. Nothing else is installed on your computer, and there is no setup step any more.

**The Docker image now has its server configuration.** The image published with 0.2.0 ran with nginx's default configuration, without the Content-Security-Policy, the security headers and the Ollama Cloud route that Compose added. The image now carries its own configuration, and a test in the CI starts it, with Compose and with plain `docker run`, and checks the headers. If you ran `docker run ghcr.io/balalex12/trazo:0.2.0`, update to this version.

**Recording in the desktop app.** The recorder now works with all its modes in the installers (canvas, canvas with live maps and the whole app), as it does in a browser. Before, the whole-app mode was missing from the desktop app.

**Windows.** The command line tools (`hyperframes-render`, the notebook build and the Jupyter proxy) did nothing at all on Windows; fixed in this version.

## Status and known limits

- Verified with automated tests, the CI (which builds every image and starts them) and by hand.
- Rendering a video with HyperFrames and the local voice (`tools/hyperframes-render.mjs`) needs FFmpeg, Chrome and Python; the MP4 and GIF export inside the app needs nothing.
- Interactive map embeds appear as a placeholder in exported video.
